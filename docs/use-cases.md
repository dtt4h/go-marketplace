# Use Cases

## Роли

| Роль | Описание |
|------|----------|
| Гость | Неавторизованный пользователь |
| Покупатель | Авторизованный пользователь с ролью `buyer` |
| Продавец | Авторизованный пользователь с ролью `seller` |
| Админ | Авторизованный пользователь с ролью `admin` |

Пользователь может быть одновременно покупателем и продавцом.

---

## UC-1: Регистрация

**Актёр:** Гость  
**Цель:** Создать аккаунт для покупок

1. Гость открывает страницу регистрации.
2. Вводит email, пароль, имя, фамилию.
3. Система проверяет email на уникальность.
4. Система создаёт пользователя с ролью `buyer`, выдаёт access + refresh token.
5. Гость перенаправляется в личный кабинет.

**Альтернативы:**
- Email уже занят → ошибка `CONFLICT`, предложение войти.
- Пароль слабый → ошибка валидации.

---

## UC-2: Вход

**Актёр:** Гость  
**Цель:** Авторизоваться

1. Гость вводит email и пароль.
2. Система проверяет учётные данные.
3. Выдаёт access + refresh token.
4. Гость перенаправляется на главную.

**Альтернативы:**
- Неверный пароль → ошибка `UNAUTHORIZED`.

---

## UC-3: Поиск и просмотр товара

**Актёр:** Гость, Покупатель  
**Цель:** Найти и посмотреть товар

1. Пользователь открывает каталог.
2. Фильтрует по категории, цене, ищет по названию.
3. Система возвращает список товаров с пагинацией.
4. Пользователь кликает на товар → открывается карточка с описанием, фото, ценой, остатком, магазином.

---

## UC-4: Добавление в корзину

**Актёр:** Покупатель  
**Цель:** Собрать товары для заказа

1. Покупатель на карточке товара нажимает «В корзину».
2. Товар добавляется в корзину (локальный стейт + опционально Redis).
3. Покупатель может изменить количество или удалить товар в корзине.

---

## UC-5: Оформление заказа

**Актёр:** Покупатель  
**Цель:** Создать заказ и оплатить

1. Покупатель открывает корзину, нажимает «Оформить заказ».
2. Вводит адрес доставки.
3. Система проверяет наличие товара на складе, резервирует количество.
4. Создаётся заказ со статусом `pending`.
5. Покупатель перенаправляется на оплату.

**Альтернативы:**
- Товара нет в наличии → ошибка, товар убирается из корзины.
- Товар изменил цену → обновляется в корзине, покупатель подтверждает.

---

## UC-6: Оплата заказа

**Актёр:** Покупатель  
**Цель:** Оплатить заказ

1. После оформления заказа инициируется платёж.
2. Покупатель перенаправляется на страницу платёжного провайдера.
3. После оплаты провайдер вызывает webhook.
4. Система обновляет статус платежа на `succeeded`, статус заказа на `paid`.
5. Покупатель видит подтверждение оплаты.

**Альтернативы:**
- Оплата не прошла → статус платежа `failed`, заказ остаётся `pending`.
- Покупатель закрыл страницу → может повторить оплату из истории заказов.

---

## UC-7: Отмена заказа

**Актёр:** Покупатель, Продавец  
**Цель:** Отменить заказ

1. Покупатель или продавец нажимает «Отменить заказ».
2. Если заказ оплачен — инициируется возврат средств.
3. Статус заказа → `cancelled`, статус платежа → `refunded`.
4. Зарезервированный товар возвращается на склад.

**Альтернативы:**
- Заказ уже доставлен → отмена невозможна.

---

## UC-8: Регистрация магазина

**Актёр:** Покупатель  
**Цель:** Стать продавцом

1. Покупатель в личном кабинете нажимает «Стать продавцом».
2. Заполняет название, описание, логотип магазина.
3. Система создаёт магазин, обновляет роль пользователя на `seller`.
4. Продавец получает доступ к панели управления магазином.

---

## UC-9: Добавление товара

**Актёр:** Продавец  
**Цель:** Выставить товар на продажу

1. Продавец открывает панель магазина, нажимает «Добавить товар».
2. Заполняет: название, описание, цену, остаток, категорию.
3. Загружает изображения (загружаются в S3, возвращаются URL).
4. Товар создаётся со статусом `pending` (на модерации).
5. Админ проверяет и активирует товар → статус `active`.

---

## UC-10: Управление заказами продавцом

**Актёр:** Продавец  
**Цель:** Обработать заказы

1. Продавец открывает список заказов своего магазина.
2. Видит заказы с товарами своего магазина.
3. Меняет статус: `paid` → `shipped` → `delivered`.
4. Может отменить заказ, если не может выполнить.

---

## UC-11: Модерация товара

**Актёр:** Админ  
**Цель:** Проверить товар перед публикацией

1. Админ открывает список товаров на модерации (`pending`).
2. Просматривает карточку товара.
3. Одобряет → статус `active`, или отклоняет → статус `rejected` с причиной.
4. Продавец видит результат в панели магазина.

---

## UC-12: Просмотр истории заказов

**Актёр:** Покупатель  
**Цель:** Посмотреть свои заказы

1. Покупатель открывает «Мои заказы».
2. Видит список заказов с фильтром по статусу.
3. Кликает на заказ → детали: товары, суммы, статус, адрес.
