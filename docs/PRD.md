# PRD: Маркетплейс — MVP

## 1. Описание продукта

Веб-платформа маркетплейса, объединяющая продавцов и покупателей. Продавцы могут создавать витрину товаров, управлять каталогом и заказами. Покупатели могут искать товары, оформлять заказы и оплачивать их онлайн.

## 2. Целевая аудитория

- **Продавцы** — малый и средний бизнес, индивидуальные предприниматели.
- **Покупатели** — физические лица, ищущие товары в одном месте.
- **Администраторы** — модерация площадки, управление пользователями и контентом.

## 3. Пользовательские роли

| Роль | Описание |
|------|----------|
| `buyer` | Покупатель: поиск товаров, корзина, оформление и оплата заказов, просмотр истории заказов. |
| `seller` | Продавец: управление каталогом товаров, просмотр и обработка заказов, управление магазином. |
| `admin` | Администратор: модерация товаров, управление пользователями, просмотр аналитики. |

Пользователь может быть одновременно покупателем и продавцом.

## 4. Функциональные требования (MVP)

### 4.1. Auth (Аутентификация и авторизация)
- Регистрация по email + пароль + username.
- Вход по email + пароль.
- JWT-токены (access 15m + refresh 7d), ротация refresh при обновлении.
- Logout — завершение всех сессий пользователя.
- Управление ролями.
- Восстановление пароля по email (forgot-password / reset-password).

### 4.2. Users (Пользователи)
- Профиль пользователя: имя, email, аватар, контакты.
- Заявка на статус продавца (подача заявки → модерация админом → создание магазина).
- Управление профилем.
- История заказов (для покупателя).
- Управление магазином (для продавца).

### 4.3. Products (Товары)
- Создание, редактирование, удаление товаров (продавец).
- Загрузка изображений товара.
- Категории и подкатегории товаров.
- Поиск по названию, фильтрация по категории, цене, продавцу.
- Карточка товара с описанием, ценой, изображениями, остатком.
- Модерация товаров (админ): одобрение, отклонение с причиной, архивирование.

### 4.4. Orders (Заказы)
- Добавление товаров в корзину.
- Оформление заказа из корзины (авторизованный или гостевой).
- Выбор адреса доставки.
- Статусы заказа: `pending` → `paid` → `shipped` → `delivered` / `cancelled`.
- Автоматическая отмена неоплаченных заказов через 24 часа.
- Просмотр истории заказов (покупатель).
- Просмотр и обработка заказов (продавец).
- Отмена заказа.
- Трек-номер доставки.

### 4.5. Payments (Платежи)
- Оплата заказа картой через платёжный шлюз.
- Статусы платежа: `pending` → `succeeded` / `failed` / `refunded`.
- Возврат средств при отмене заказа.
- История транзакций.

## 5. Нефункциональные требования

| Параметр | Требование |
|----------|------------|
| Производительность | Отклик API < 300 мс (p95) |
| Доступность | 99.5% (MVP) |
| Безопасность | HTTPS, хеширование паролей (bcrypt), JWT |
| Масштабируемость | Модульный монолит, готовый к выделению сервисов |
| Логирование | Структурированные логи (JSON), уровни: debug/info/warn/error |
| Мониторинг | Health-check эндпоинт, метрики Prometheus |

## 6. Ограничения MVP

- Нет системы отзывов и рейтингов.
- Нет системы скидок и промокодов.
- Нет мультиязычности.
- Нет мобильного приложения (только веб).
- Один способ оплаты (банковская карта).

## 7. Метрики успеха

- Конверсия из просмотра товара в заказ.
- Процент успешных платежей.
- Среднее время оформления заказа.
- Количество активных продавцов за месяц.
