# ADR-003: Архитектура фронтенда

**Дата:** 19.07.2026  
**Статус:** принято

## Контекст

Фронтенд маркетплейса — SPA на React. На MVP нужно покрыть: каталог, карточку товара, корзину, оформление заказа, личный кабинет покупателя и продавца. Важно не переусложнить структуру, но оставить возможность расти.

Рассматривались два подхода: Feature-Sliced Design (FSD) и простая feature-based структура.

## Решение

**Feature-based структура** — простой и понятный подход, достаточный для MVP.

```
src/
├── api/              # HTTP-клиент, функции запросов по доменам
│   ├── auth.ts
│   ├── products.ts
│   ├── orders.ts
│   └── payments.ts
├── components/       # Общие UI-компоненты (кнопки, инпуты, модалки)
├── pages/            # Страницы, привязанные к роутам
│   ├── CatalogPage.tsx
│   ├── ProductPage.tsx
│   ├── CartPage.tsx
│   ├── CheckoutPage.tsx
│   ├── ProfilePage.tsx
│   └── SellerDashboardPage.tsx
├── hooks/            # Общие хуки (useAuth, useCart, usePagination)
├── store/            # Глобальный стейт (Zustand)
│   ├── authStore.ts
│   └── cartStore.ts
├── types/            # Общие TypeScript-типы
├── utils/            # Утилиты (форматирование цены, дат)
├── App.tsx           # Роутинг, layout
└── main.tsx          # Точка входа
```

### Почему не FSD

FSD — мощная архитектура, но для MVP это лишние слои (entities, features, widgets, segments, public API). Команда небольшая, скорость важнее. Когда проект вырастет — можно мигрировать, так как файлы уже сгруппированы по доменам в `api/`.

### Стек

| Компонент | Технология |
|-----------|------------|
| Фреймворк | React 18 + TypeScript |
| Сборка | Vite |
| Роутинг | React Router v6 |
| Стили | Bootstrap CSS |
| HTTP | Axios |
| Стейт | Zustand (простой, без бойлерплейта) |
| Валидация | react-hook-form + zod |

## Итог

Feature-based структура даёт понятную организацию кода без оверинжиниринга. Каждый файл на своём месте, новый разработчик разберётся за 10 минут.
