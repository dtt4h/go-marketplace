# ADR-003: Архитектура фронтенда

**Дата:** 19.07.2026  
**Статус:** принято, обновлено 27.07.2026

## Контекст

Фронтенд маркетплейса — SPA на React. На MVP нужно покрыть: каталог, карточку товара, корзину, оформление заказа, личный кабинет покупателя и продавца. Важно не переусложнить структуру, но оставить возможность расти.

Рассматривались два подхода: Feature-Sliced Design (FSD) и простая feature-based структура.

## Решение

**Feature-based структура** — простой и понятный подход, достаточный для MVP.

```
src/
├── app/                        # Инициализация приложения и роутинг
│   ├── router/
│   └── App.tsx
├── features/                   # Функциональные модули
│   ├── auth/
│   │   ├── api/
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── store/
│   │   └── types.ts
│   ├── profile/
│   │   ├── api/
│   │   ├── components/
│   │   └── types.ts
│   ├── catalog/
│   ├── cart/
│   └── orders/
├── pages/                      # Страницы, привязанные к маршрутам
│   ├── AuthPage.tsx
│   ├── ProfilePage.tsx
│   ├── CatalogPage.tsx
│   ├── ProductPage.tsx
│   ├── CartPage.tsx
│   └── CheckoutPage.tsx
├── shared/                     # Код без привязки к одной функции
│   ├── api/                    # Общий HTTP-клиент
│   ├── assets/
│   ├── styles/
│   ├── ui/                     # Общие кнопки, поля и модальные окна
│   └── utils/
└── main.tsx                    # Точка входа
```

Страницы собирают функциональные модули, а не содержат доменную
логику. Компоненты, API, состояние и типы конкретного сценария
располагаются внутри соответствующей папки в `features/`. В
`shared/` попадает только код, который не принадлежит одной
конкретной функции продукта.

### Почему не FSD

FSD — мощная архитектура, но для MVP это лишние слои (entities,
widgets, segments, public API) и строгие правила импортов. Команда
небольшая, поэтому используются только необходимые границы:
`app`, `pages`, `features` и `shared`. Если проект вырастет, эти
модули можно постепенно перенести в полноценные слои FSD.

### Стек

| Компонент | Технология |
|-----------|------------|
| Фреймворк | React 19 + TypeScript |
| Сборка | Vite |
| Роутинг | React Router v7 |
| Стили | SCSS Modules |
| HTTP | Axios |
| Стейт | Zustand (простой, без бойлерплейта) |
| Валидация | react-hook-form + zod |

## Итог

Feature-based структура даёт понятную организацию кода без оверинжиниринга. Каждый файл на своём месте, новый разработчик разберётся за 10 минут.
